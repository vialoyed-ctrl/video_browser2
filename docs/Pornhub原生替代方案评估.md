# Pornhub 原生替代方案评估

## 结论

当前已撤下应用内 WebView 方案。可核实到的 WebMaster 接口适合公开视频目录、搜索、分类和元数据展示；社区文档还提到视频嵌入代码。但现有证据不足以证明它提供消费者账号登录、订阅/收藏同步或可直接交给本项目原生播放器的稳定授权播放地址。Pornhub 官方站和 Hubtraffic API 文档页目前无法从本环境访问，因此这些接口的现行可用性、许可条件和完整能力仍需官方资料确认。

因此，**没有找到一个可验证且能同时满足“完全原生 UI、站内登录/订阅/收藏、官方播放、全广告过滤”的开源替代软件**。不应把非官方网页解析包装成稳定的官方 API。

## 可落地的原生界面方案

若先交付不含 WebView 的目录体验，可以按 Flutter 原生页面拆分：

```text
Pornhub 模块入口
  ├─ 首页/分类页
  ├─ 搜索页与筛选/分页
  ├─ 海报网格与视频详情
  └─ 本地历史/本地收藏（仅保存在本 App）
       └─ Dio → 可授权的目录 API → 原生 Model/Repository
```

WebMaster 接口在第三方开源文档中被描述为 Pornhub 官方的站长 API，提供搜索、分类、视频信息和嵌入代码；例如 [Pornhub.js 文档](https://github.com/pionxzh/Pornhub.js) 与 [PHUB 文档](https://phub.readthedocs.io/en/latest/guides/pkg-usage.html)。不过这些项目并非 Pornhub 官方客户端 SDK，且不能据此推断用户登录和站内互动接口已开放。

## 功能边界

| 需求 | 无浏览器的原生方案现状 |
|---|---|
| 自定义 Flutter 页面、搜索、分类、分页、海报列表 | 可用目录/元数据接口实现，需先验证接口当前可访问及允许用途 |
| 详情页元信息 | 可用公开元数据实现 |
| 本地收藏、稍后看、历史 | 可由 App 本地实现，但不会同步 Pornhub 账号 |
| 官网账号登录、订阅、官网收藏同步 | 未发现可核实的官方消费者认证/互动 API |
| 官网视频原生起播、复用项目播放器 | 官方资料仅能核实到嵌入代码；没有验证到可供本地播放器使用的官方媒体 API |
| 百分之百屏蔽广告 | 无法承诺；官方播放器可能包含站点自身的广告内容，强行阻断可能破坏播放，也会绕开网站的商业呈现 |

社区解析库会抓取官网页面并提取数据；其中 PHUB 文档明确提示这种做法可能违反 Pornhub 服务条款，并且站点改版、验证码、年龄检查和登录保护都可能令其失效。它不适合作为要求稳定运行的正式模块。

## 要完成完整需求所缺的条件

需要 Pornhub/授权合作方提供并允许 App 使用的接口文档或 SDK，至少覆盖：消费者 OAuth/登录、订阅/收藏等账号操作、可授权的原生播放地址或原生播放器 SDK，以及广告处理规则。拿到这些资料后，可以按项目现有 `VideoSource`、`PlayerView` 和本地清单服务接入，UI 全部由 Flutter 绘制。

在取得这些接口前，唯一不依赖 WebView 的安全交付范围是**原生目录/搜索 + App 本地清单**；它不等同于可登录、可同步官网账号并在统一播放器内完整播放的 Pornhub 模块。
